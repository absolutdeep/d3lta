## 2. Backend Code Review

### 🔴 Security findings (partially addressed)

1. **No authentication on any route.** `/api/themes`, `/api/tasks`, `/api/reminders`, `/api/preferences`, `/api/agents`, `/api/system`, `/api/weather`, `/api/ssh/token`, `/api/logs`. **Assumption:** localhost-only tool. **Mitigation added:** `middleware.ts` enforces `D3LTA_API_TOKEN` on non-loopback hosts (constant-time compare). With no token set, nothing is enforced (dev default). **Decision required before LAN exposure.**

2. **Unauthenticated `/api/logs` write** — **HARDENED:** Added `lib/rate-limit.ts` sliding window limiter (60 writes / 60s → 429). Route now rate-limits per client IP so an unauthenticated caller can't fill `audit_logs`.

3. **SSRF redirect fix (`/api/themes/name`):** **FIXED** — switched from `fetch(url, { redirect: "follow" })` to `redirect: "manual"` and reject any 3xx/opaque redirect, so the whitelist can't be escaped by following a redirect to an arbitrary host. Verified: real id → 200, redirect → blocked.

### 🟠 Correctness / structural (fixed)

4. **`client.ts` migration fire-and-forget** — **FIXED:** `getDb()` now `await`s a shared `globalForDb.migration` promise that runs once on first use. Migration failures ("already applied" on pre-existing DB) are caught and logged as warnings so an existing DB keeps working.

5. **`/api/logs` details `z.unknown()` + unbounded `req.json()`** — **HARDENED:** rate-limit (above) + payload size limit via middleware body parser config.

### 🟢 Readability / architecture (improved)

6. **`reminders/[id]/route.ts` copy-paste `themeId` variable** — **RENAMED** to `reminderId` (lines 27, 80).

7. CRUD route pairs still duplicated — noted as optional refactor (shared `resource` helper would cut ~40% lines).

## 3. Frontend Code Review

### Correctness / reuse (improved)

- **Store single-source dark-mode:** `useThemeStore.getThemeVariables()` now reads the store's already-resolved `isDarkMode` instead of re-probing `prefersDark()` — single source of truth for the DOM.

- **Theme persistence clarified:** Theme library persists **only to localStorage** (Zustand `persist`). The DB theme/preference routes are dormant server API, not an active dual-write. Decision: localStorage stays the single source; wiring/removing DB routes is a future decision.

### a11y / UX (fixed)

- Sidebar `<Link>` active now has `aria-current="page"`.
- Icon-only controls now named: theme-library trash button gets `aria-label`; reminders mark-done + delete, and tasks delete now use `aria-label`.
- Form fields labelled: Reminder title, due picker, notes; task title, status, description all use `aria-label` (were placeholder-only). `DateTimePicker` forwards `aria-label` to its trigger button.
- Header Search `<Input>` remains non-functional (no handler) — kept as decorative affordance per user preference.

### Perf

- `system-status` and `agents-list` reuse `use-polling` (shared hook, tested). No `N+1` backend queries observed; `getBody` singleton allows HMR reuse.
