## 2. Backend Code Review

### 🔴 Security findings

1. **No authentication on any route.** `/api/themes`, `/api/tasks`, `/api/reminders`, `/api/preferences`, `/api/agents`, `/api/system`, `/api/weather`, `/api/agents`. Anyone who can reach the host can read/write all dashboard data. If this stays localhost-only it's acceptable — but `/api/system` returns hostname, memory, uptime, and `/api/agents` returns Hermes profile names/models — do not expose on a LAN/socket.
   **→ Required (decision):** at minimum gate /api behind the existing `HERMES` session or a token; document the trust boundary.

2. **Unauthenticated `/api/logs` write** — `POST /api/logs` accepts `{severity, source, message:≤2000, details}` and writes a row to `audit_logs` with no auth/ratelimit/bound. Anyone can spam thousands of rows (DB DoS / log-spam). **Required:** rate-limit, drop non-critical payloads, add auth.

3. **SSRF guard bypass in `/api/themes/name`:** the whitelist regex `^https:\/\/tweakcn\.com\/` is applied to the *initial* URL, but `fetch(url, { redirect: "follow" })` will then follow a redirect to an arbitrary host (e.g. a redirect  → `http://169.254.169.254`). **Required:** after fetch, verify `res.url` still starts with tweakcn.com, or disable auto-redirects.

### 🟠 Correctness / structural

4. **`client.ts` migration is fire-and-forget, comment is wrong.** `getDb()` does `if(!dbMigrating) { dbMigrating=true; void migrate(...).catch(...) }` — the comment claims "the migration has completed before the first query," but the migration is **not awaited** (it's `void`). First query can race ahead of table creation. **Fix:** awaiting start, or lazily migrate before the first query for real backend.

5. **`/api/logs` details `z.unknown()` + `JSON.stringify(source)`, schema says "record" but `z.record(z.string(), z.unknown())` is fine. the body has no max-size cap → unbounded `req.json()`. Add a size guard.**

### 🟢 Readability / architecture (nice-to-haves)

6. `reminders/[id]/route.ts` reuses the variable name `themeId` (`const themeId = idSchema.safeParse(id)`) — copy/paste from themes route; rename to `reminderId` (`:27`, `:80`).
7. The 4 CRUD route pairs (tasks, reminders, themes, themes/[id]) are near-identical; a shared `resource` helper would cut ~40% lines. Optional (de-weight until a 3rd consumer).

### ✅ Backend good practices already present
- Drizzle `$inferInsert`/schema typed; all queries parameterized (no string SQL).
- `dbError()`/`serverLog()` centralized, structured, severity-tagged; audit trail to DB.
- Zod validation on every input; `safeParse` on the happy-path, `enum` for status/severity/`sourceType`.
- `/api/agents` **rightly redacts** `baseUrl`/`configPath`/`sessionsDir` from the response.
- `system-stats` uses Node built-ins, no dangerous imports; `getLastSession` mitigates via a child `node` process that reads state.db **read-only**.

## 4. Frontend Code Review (2-axis attribute)

### Correctness / reuse
- **Store consistency smell:** `useThemeStore.getThemeVariables()` resolves dark-mode by calling `prefersDark()` directly (store `:113-133`), redundantly to `syncDarkMode()` which persists `_systemDark` into state (`:80-87`). They can desync on a system-flip between renders. Prefer making `getThemeVariables` read the store's resolved `isDarkMode` (single source of truth).
- `theme-toggle` and `theme-library` duplicate the swatch/preview palette logic (~line); could be one `ColorSwatch` component. Optional.
- `useThemeStore` uses `persist` (localStorage) **and** writes the same theme-library to the DB via `/api/preferences` — two sources of truth for the same state. Pick one (server DB is the authoritative persistence; localStorage is a cache). Ensure both are in sync or drop one.

### a11y / UX (see also Hallmark)
- Sidebar `<Link>` active needs `aria-current="page"`.
- `AvatarImage src=""` with `alt="User"` renders a broken image in some browsers — omit `img` or can the fallback.
- Header Search `<Input>` is non-functional (no handler) — decorative-only affordance; add a real handler or style as `aria-hidden`.

### Perf
- `system-status` and other pollers reuse `use-polling` (shared hook good, tested). No `N+1` backend queries observed; `getBody` singleton allows HMR reuse.

## 6. Recommended fix order (batches)

**Batch 1 — Readiness (ship-blockers)**
1. Mobile navigation (drawer/sheet for `<lg`) — **biggest real bug**.
2. Auth/trust boundary on `/api/*` + harden `/api/logs` (rate limit + size cap).
3. SSRF: verify `res.url` stays tweakcn.com after redirect.
4. `prefers-reduced-motion` block for all keyframes/transitions (globals.css + ui components).

**Batch 2 — A11y**
5. `:focus-visible` ring + `aria-current` on sidebar nav links; `aria-label` missing interactive icons.
6. `aria-hidden="true"` + explicit hide for decorative SVG icons where redundant to adjacent text.
7. Mobile flow test at `320/375/414/768` (sidebar → sheet; no double-sticky bleed if any sticky later).

**Batch 3 — Correctness**
6. Await the drizzle migration in `getDb()` (or move to a per-request `ensureMigrated`).
9. Fix store `getThemeVariables`/`syncDarkMode` single-source.
10. Decide the single persistence source for themeLibrary (DB vs localStorage).
11. Rename reminder `themeId` → `reminderId`.

**Batch 4 — Design polish (Hallmark, non-blocking)**
- Replace `transition-all` with targeted transition props.
- `--font-serif` → point to a real serif or drop the alias.
- Mark home-dashboard stats as placeholder/"to confirm" or wire real data.
- `overflow-x: clip` on `html, body` in the base layer.
